# ADR 0010: ステージ解放

## 状態

Accepted／M4実装中

## 背景

ステージ1〜3を最初からすべて選べると、ステージ2クリアで再生速度が開く進行と、ゲーム内の学習順が一致しない。既存の進捗保存にはステージごとのクリア記録があるため、新しい保存形式を増やさずに段階的な入口を作れる。

## 決定

- ステージ1は常に選べる。
- ステージ1のクリア記録があるとステージ2を選べる。
- ステージ2のクリア記録があるとステージ3を選べる。
- 未解放カードは無効化し、「前のステージをクリアすると解放」と表示する。
- 既存のクリア記録を読み込み時の解放判定へ使う。ステージ2または3の既存記録がある場合は、その記録に対応するステージを開く。
- 解放状態はApplication側で計算し、StageSession、StageReplay、進捗保存v2のschemaは変更しない。
- 解放は選択画面だけに適用し、現在進行中のセッションや結果表示を変更しない。

## 禁止事項

- 未解放ステージをURL、DOMイベント、保存値の書き換えで開始できるようにしない。
- クリア記録がないのに解放済みとして保存しない。
- ステージ解放のために水流計算、評価、候補列、雨列を変更しない。
- 既存保存を、解放状態だけを理由に破棄しない。

## 検証

- 新規状態ではステージ1だけが挑戦可能であること。
- ステージ1記録でステージ2、ステージ2記録でステージ3が開くこと。
- 既存のステージ2または3記録を読み込んだ場合に対応するステージが開くこと。
- 不明なステージIDを解放しないこと。
- 型検査、全単体テスト、ドメイン／画面build・smokeを通す。

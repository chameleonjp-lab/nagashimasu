# ADR 0013: M4施工プレビュー説明

## 状態

Accepted／M4ゲーム性検証中

## 背景

盤面上の色や矢印だけでは、確定前に何が変わるかを読み取りにくい場合がある。特に小さな画面や読み上げを使う場合は、施工セル、当手の雨、この手の水流を最後まで処理した結果を短い文章でも確認できる方が安全である。

## 決定

- 確定前の有効な施工プレビューに、次の4行を表示する。
  - 施工: 変更するセルと、何段上げるか／下げるか
  - 降雨: この手に発生する雨の量とセル。雨がなければその旨
  - 水流: 本番と同じ固定ステップをすべて処理した後の、移動量、安全排水、危険流出、保護セル浸水
  - 見込み: この手の後も継続、クリア、失敗のいずれになるか。失敗時はDomainが返した理由を表示する
- 文章は`StageSession.preview()`が返す`StageTurnPreview`だけから作る。Presentation側で地形や水流を再計算しない。
- 仮置きがない、または配置が無効なときは説明欄を隠す。既存の危険度表示とThree.js表示は残す。
- 説明文の生成は表示専用であり、セッション状態、候補、手数、タイマー、操作記録、StageSaveを変更しない。

## 保持するもの

- 予測は施工後・降雨後の`flowStepsPerTurn`回の水流までとする。`nextFlow`は既存の最初の固定ステップとの一致検査用に残し、最終盤面と見込みは全ステップの結果から作る。
- 「施工確定」だけが手番を進め、指を離す、候補を選ぶ、回転する、文章を読むだけでは確定しない。
- Previewと実行traceの一致を既存のStageControllerテストで確認する。

## 検証

- ステージ1で施工セルと高さ変更が文章へ反映されることを確認する。
- ステージ3の2手目で、予報と同じ雨セル・雨量が文章へ反映されることを確認する。
- 最初の水流では危険がなくても後の固定ステップで失敗するケースを、最終見込みへ反映することを確認する。
- `boardAfterTurn`が確定後の盤面と一致し、盤面表示も1ステップ後ではなく手番終了後の水量を使うことを確認する。
- プレビュー前後で可逆ゲーム状態のhashが変わらないことを確認する。
- 型検査、全単体テスト、ドメイン／画面build・smoke、`git diff --check`を通す。

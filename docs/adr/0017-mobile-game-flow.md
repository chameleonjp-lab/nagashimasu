# ADR 0017: スマートフォンの一手を操作シートへ分ける

- **状態:** Accepted／iPhone実機再検証待ち
- **日付:** 2026-08-31（JST）

## 背景

実機画像では、目的、盤面、セル番号表、候補、確定ボタン、結果が長いページへ連続して配置されていた。プレイヤーは候補を見たあと盤面へ戻り、さらに下へ戻って確定する必要があり、1手の順番を理解できなかった。

また、固定カメラでは低いセルや池が隣の地形に隠れ、セル番号と画面上の位置を確認しにくかった。

## 決定

- スマートフォンでは、盤面を画面の主領域に置く。
- 施工候補、施工プレビュー、確定・取消・見送りは、画面下の操作シートに置く。
- 操作シートを開閉しても、仮置きした候補は保持する。
- 候補を選んだ後は盤面へ戻り、盤面をタップして置く。置いた後は操作シートを開いて予測を確認する。
- 凡例とセル番号表は補助情報として折りたたみ、初回の操作対象から外す。
- 盤面は90度単位で回転できる。回転は描画、入力、雨予報、水流表示で共有する。
- 池は水量が0でも輪郭と「池へ」の表示を出す。
- 失敗時は、危険辺と関係するセルを盤面上で強調する。
- ポインターが中断されても、意図的な仮置きを自動解除しない。

## 変更しないもの

- Domainの水流計算、クリア条件、スコア、操作ログ
- 施工候補のルールとステージの雨列
- 途中保存の互換性境界
- PCの横向きレイアウト

## 却下した案

- すべての情報を縦に並べたまま、文字や色だけを調整する案は、操作順の問題を解決しないため採用しない。
- 盤面を自由に回す独立の描画処理と入力処理は、セルのずれを再発させるため採用しない。
- 盤面操作中の`pointercancel`で仮置きを消す案は、画面操作をプレイヤーの意図しない失敗にするため採用しない。

## 検証

- 4方向それぞれで、全64セルの中心が同じ論理セルへ戻ることを単体テストする。
- 390px、402px、430px幅で、操作シートを開いても横スクロールが発生しないことを確認する。
- 候補選択、盤面配置、予測確認、施工確定をページの上下移動なしで行う。
- 空の池、雨、現在の水、危険辺、結果の漏水セルを実機で見分けられることを確認する。
- 通常のタッチ中断後も仮置きが保持されることを確認する。

# ADR 0015: 初見プレイの理解導線

- **状態:** Accepted／M4実機再検証待ち
- **日付:** 2026-08-29（JST）

## 背景

M4のiPhone実機初見テストで、プレイヤーが「何をするゲームか」「次に何をすればよいか」「何が起きたか」を理解できないまま終了した。既存画面にはチュートリアル、候補、予報、凡例、結果欄が存在したが、情報が別々に配置され、最初の行動と結果の因果が一続きになっていなかった。

## 決定

- タイトル画面で、ゲームの目的を「雨水の流れを変えるパズル」と明記する。
- 選択中ステージのクリア条件を、ゲーム用語だけでなく「池に雨水を24ためる」のような具体的な文で表示する。
- ゲーム開始後、画面上部に「今すること」を表示し、候補選択、緑の丸の選択、予測確認・進行の3段階を示す。
- 「仮置き」はまだ確定していないこと、「施工確定」はその配置で雨を進めること、「見送り」は工事をせず雨を進めることを操作ボタン内に表示する。
- 受理した各手番について、工事、雨の場所と量、水の移動・排水・流出、処理結果を文章で残す。表示はStageSessionのtraceを入力とし、水流の再計算は行わない。
- 既存の決定論的な水流規則、クリア判定、スコア、操作ログは変更しない。
- 実機初見テストで理解が基準未達だったため、修正後に最低3名で再テストするまでM5のステージ追加を開始しない。

## 却下した案

- 説明文を増やすだけで、ゲーム中の「今すること」を表示しない案は、実機で情報を見失った問題を解決しないため採用しない。
- プレイヤーに正解手順を強制する案は、候補比較と試行錯誤を奪うため採用しない。
- 水流を表示側で再計算して結果説明を作る案は、Domainの判定と表示の不一致を生むため採用しない。

## 検証

- `turn-outcome` の純粋な要約関数で、施工・雨・水流・結果の接続を検査する。
- app smokeで、初回説明、手番ガイド、操作説明、手番結果表示が本番バンドルに含まれることを検査する。
- M4プレイテストプロトコルで、目的理解、最初の施工、漏水原因の説明、継続意欲を修正後に再測定する。

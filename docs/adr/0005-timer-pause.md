# ADR 0005: 思考時間と一時停止

## 状態

Accepted／M4実装中

## 背景

M4では、ステージ3以降の緊張感を段階的に導入しつつ、タッチ操作や端末のバックグラウンド化を失敗として扱わない必要がある。壁時計をDomainへ渡すと、再現性とリプレイ契約を壊すため、時間処理はApplication／Platformへ隔離する。

## 決定

- ステージ1・2は時間制限なし。ステージ3は標準20秒を基準とする。
- 思考時間設定は`standard`、`extended`、`unlimited`の3値とする。`extended`は基準秒数の1.5倍を整数ミリ秒へ丸め、`unlimited`はタイマーを作らない。
- タイマーは`awaiting-turn`の思考中だけ動く。施工、雨、水流、評価のtrace再生中は停止し、再生完了後に次の手番のタイマーを新しく開始する。
- 手動一時停止とPage Visibilityによる自動一時停止は、現在の残り時間を保存して停止する。復帰はその残り時間から再開し、バックグラウンド滞在時間を消費しない。
- 一時停止中は候補、仮置き、回転、確定、見送り、Undoを受け付けない。仮置きは自動確定しない。
- 残り3秒以下はHUDの警告表示を有効にする。タイマー設定はスコアへ影響させない。
- 期限到達時はApplicationが現在の`actionId`と`expectedRevision`でStageSessionの明示的な`timeout`操作を一度だけ送る。Domain側のrevision／action ID検査が、確定タップとの競合を直列化する。
- 無制限設定では期限到達callbackを作らず、Domainの`timer-disabled`拒否契約を維持する。
- タイマーのruntimeは`now`、schedule、cancelの注入境界を持つ。単体検査では壁時計をFakeRuntimeへ置き換え、古いcallback、停止中の時間消費、期限到達の一度性を検証する。

## 禁止事項

- `StageSession`、StageReplay、評価値へ経過ミリ秒、`Date.now()`、`performance.now()`、描画フレーム時刻を渡さない。
- 時間切れで仮置きを確定しない。
- 再生中、結果表示中、チュートリアル中にタイマーを進めない。
- Page Visibility復帰時に古いタイマーを残したまま新しいタイマーを二重開始しない。

## 未実装範囲

進行状況のlocalStorage保存、リロード後の復帰、音・振動による警告、実機での端末受入は後続のM4／M6作業とする。一時停止状態は現時点ではページ内メモリだけに保持する。

## 検証

- 標準／長め／無制限の時間変換
- 一時停止中の非消費と復帰後の期限到達
- 既にキューへ入った古いcallbackの無効化
- 雨・水流再生中のタイマー停止と手番復帰時の再開（画面ビルドで確認）

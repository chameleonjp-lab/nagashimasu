# PR2：水流の各段階と水量表示をそろえる

2026-09-08。Astra highの監査計画F01に対応する。基点はPR1マージ後のmain `d8b7c6ab6b29b952a77942fdf61eac6dc7f3d158`。Draft PRの対象SHAはPR本文にも記録する。

## 解消する問題

修正前は、施工前と雨後は別の盤面を表示していたが、水流の4区間では確定後の最終盤面を表示していた。流れの線・粒子と水塊・数字が別の時点を指すため、どこへ水が移ったかを追えなかった。

## 実装

- `StageTraceEvent.flowResult` の `transfers` と `drains` だけを使い、雨後から水流1〜4回後までの表示用 `BoardSnapshot` を一度作る。
- 表示用のApplication関数は水流ソルバー、流向判定、勝敗判定を呼ばない。差分を `BoardState.applyFlowResult` へ渡して台帳と範囲だけを検証する。
- `main.ts` の再生中盤面は、施工前・雨後・該当水流後・評価のイベントに対応するスナップショットを選ぶ。Undoは復元後の確定盤面を表示する。
- 予測、雨予報、目標進捗、失敗時の強調は再生中のイベントまでの状態を使い、演出の先の結果を先に表示しない。
- `three-board-frame.ts` は水流イベントの盤面を優先し、保留中プレビューの最終水量を混ぜない。

## 完成条件の検査

ステージ2で候補Aの1マス下げをE4へ置いた後、2手目を見送ると、雨後B4=8、水流1回後C4=8、2回後D4=8、3回後E4=8、4回後F4=8となることを確認した。各段階で盤面内の水＋累積安全排水＋累積危険流出が、入った水と一致する。

セル排水、盤外の危険流出、雨なし・施工なし、Undo、同じ列の再生成、保存再開後の状態ハッシュも検査した。Domainの水流・勝敗・スコア・保存形式・Undo回数は変更していない。

## iPhoneでの確認手順

PR2の確認用URLをSafariで開き、時間制限なしでステージ2を選ぶ。候補Aの「1マス下げ」をE4へ置いて施工を確定し、次の手を「見送る」。雨の後にB4へ8が入り、4回の水流でC4→D4→E4→F4へ8が順に移ることを、数字・水塊・流れの線・粒子が同じ順番で示すか確認する。最後に結果の安全排水値が変わらず、ページを再読み込みしてもステージ進行と状態が壊れていないことを確認する。

この手順は表示時点の確認用であり、初見プレイの合否測定には使わない。

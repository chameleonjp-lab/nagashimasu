# M4 ゲーム性検証プロトコル

M4の実装完了判定は、単体テストだけでなく初見プレイヤーの観察で行う。この文書は、M5（ステージ4以降）へ進む前に同じ条件で検証できるよう、参加者、手順、記録項目、判定を固定する。

## 実施条件

- 初見プレイヤーを最低3名、実施者とは別に集める。
- 事前にルール説明、操作方法、ステージの解法、失敗原因を説明しない。
- 全員が同じビルド、同じ進捗（ステージ1のみ解放）、同じタイマー設定で開始する。
- 画面共有または手元の記録を残し、開始からステージ1の結果までを観察する。
- 実機差の確認は別ゲートとし、開発テンポを優先する場合はデスクトップまたは単一ブラウザで先に実施してよい。

## Three.js移行後の追加確認

盤面本体はThree.js WebGLへ移行したが、この移行だけではM4完了としない。従来の目的理解・操作・結果の観察に加え、同じビルドで次を確認する。

- 320／390／402／430px幅と横画面で盤面全体が切れず、操作シートに横スクロールがない。
- 4方向のカメラ回転後も、施工可能セル、セル番号、雨、水流、出口の論理位置が一致する。
- WebGL初期化失敗、context lost/restored、再生成後に仮置き、残り時間、保存、TracePlaybackの位置が失われない。
- 雨の発生源、水流の移動元・移動先、安全排水、危険流出、池、保護対象を色だけに頼らず説明できる。

この環境ではブラウザ実行ファイルを起動できなかったため、上記の実ブラウザ確認は未実施として記録する。

## 参加者への案内

最初に次の一文だけ伝える。

> 画面の情報を読みながら、雨から盤面を守るために施工してください。分からないところは質問せず、そのまま進めてください。

質問への回答、操作の助言、候補の指差しは行わない。クラッシュや入力不能などの不具合だけを復旧し、復旧内容を記録する。

## 記録シート

| 指標 | 記録方法 | 合格基準 |
| --- | --- | --- |
| 目的理解 | 開始30秒で「何をするゲームか」を本人の言葉で回答 | 3名中3名（80%以上） |
| 最初の施工 | 追加説明なしで最初の施工確定まで到達 | 3名中3名（80%以上） |
| 最初の漏水の原因 | 最初の漏水後に主原因を回答 | 3名中3名（80%以上） |
| 視覚的な因果理解 | 工事・雨・水流・結果を盤面上の動きとして説明 | 3名中3名（80%以上） |
| 誤確定 | 意図しない確定回数 ÷ 確定手数 | 20手あたり1回未満を目標 |
| 継続意欲 | 結果画面で「次の手を試したいか」を回答 | 「はい」が過半数 |
| 初見クリア | ステージ1を初回試行でクリア | 極端に低くない（目安: 3名中1名以上） |

各参加者について、`目的理解秒数`、`最初の施工までの秒数`、`漏水原因の回答（正/誤/無回答）`、`誤確定数`、`確定手数`、`継続意欲`、`初見クリア`、`観察メモ`を残す。人数が3名ちょうどの場合、80%基準は実務上「3名全員」として扱う。

## 判定と次の行動

- すべての基準を満たした場合、独立レビューへ回し、承認後にM5のステージ設計を開始する。
- 目的理解または最初の施工が不足した場合、チュートリアル、候補表示、確定導線を修正する。
- 漏水原因または視覚的な因果理解が不足した場合、予報、危険表示、施工プレビュー、地形・水・雨・水流の演出を修正する。
- 誤確定が多い場合、確定ボタン、取消、仮置き表示を修正する。物理ルールは変更しない。
- 継続意欲または初見クリアが不足した場合、手数・雨間隔・候補列を再調整する。M5のステージ追加は行わない。

検証結果はこの文書の表をコピーして日付、ビルド識別子、参加者数、合否、修正項目を追記する。個人を特定できる情報は記録しない。

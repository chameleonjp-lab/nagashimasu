# PR9：モバイル操作シートの状態読み上げ

基点はPR8マージ後のmain `949eedfd8fd377360c91644d92ffa694b30e674c`。Draft PRの対象SHAはPR本文にも記録する。

## 目的

操作シートを開いた直後に、VoiceOverが「いま何をする状態か」を一文で読めるようにする。既存の表示、候補、施工、見送り、Undo、セル確認、保存、勝敗、水流は変更しない。

## 実装

- `game-controls`へ`aria-describedby="controls-sheet-description"`を追加し、操作シート内のpolite statusを説明対象にする。
- 候補選択前、仮置き中、再生中、終端の既存モバイル状態文言を、画面上の案内と同じ内容で説明欄へ同期する。
- デスクトップでは既存の通常レイアウトを維持し、モバイル状態案内を空にして不要な読み上げを発生させない。

## 自動検査

- アプリマークアップで`aria-describedby`と説明欄のIDを検査する。
- app smokeで配布物に状態説明マーカーとCSSを含むことを検査する。
- `npm run check`（型検査、47ファイル／248テスト、Domain build・smoke、画面build・smoke）を合格させる。

## iPhone 17 Pro／VoiceOver確認手順

1. 所有者限定の確認ページでステージ1を開始し、操作シートを開く。
2. 候補選択前に「候補を選んだら、盤面をタップして置きます。」と読み上げられることを確認する。
3. 施工可能セルを仮置きしてシートを開き直し、「仮置き中です。盤面の下で予測を確認します。」と読み上げられることを確認する。
4. 施工確定後の水流再生中に状態説明が「工事・雨・水流を見ています。」となり、操作対象が無効であることと矛盾しないことを確認する。
5. 終端で「結果を確認してください。」と読み上げられ、PR8のUndo／再挑戦フォーカスが維持されることを確認する。
6. VoiceOverの読み上げ順、文字拡大、縦横画面、ページ横スクロールなしを確認する。

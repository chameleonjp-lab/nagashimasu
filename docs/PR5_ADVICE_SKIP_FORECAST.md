# PR5：次に試せる助言と見送り前の予測

基点はPR4マージ後のmain `8bdb1964e82cdeaee19e1242c0b4cc0b6433cd12`。Draft PRの対象SHAはPR本文にも記録する。

## 目的

結果を読んだあとに「何を変えて試せばよいか」を1つに絞って示し、施工しない手番も確定前に比較できるようにする。助言は現行ルールで実行可能な範囲を参照するが、根拠のない正解座標は出さない。

## 実装

- 結果の助言へステージ目標と、終端手前に選ばれていた候補の施工可能範囲を渡す。保護セルそのものを上げるような曖昧な指示はやめ、施工可能な範囲から候補を選び、プレビューで目的・危険理由の変化を確認する文章へ揃えた。
- 池・安全排水・保護の目的ごとに助言を分け、池ステージで安全排水だけを勧める誤案内を避ける。座標を正解として固定せず、施工可能な場所の数だけを示す。
- `StageTurnPreview`へ手番後のmetrics・score・目的進捗を保持し、既存の純粋な`previewSkip`を使った「現在／見送り後の予測／成否／予測スコア」を操作シートへ追加した。
- 危険度の文章も目的に合わせ、安全排水が池の目標と両立するか確認すべきことを明示する。
- 見送り予測は表示専用で、候補・仮置き・操作ログ・保存値を変更しない。既存の施工確定、見送り、タイムアウト、Undo経路は変更しない。

## 自動検査

- `npm run check`: 型検査、単体テスト、ドメインbuild・smoke、画面build・smoke。
- 池・出口・保護の各目的で助言が目的と施工可能範囲を参照すること、保護セルを直接の正解座標にしないこと、池ステージで安全排水を勧めないことを検査する。
- `previewSkip`の予測が実行後の盤面・metrics・score・phase・目的進捗と一致すること、表示中にセッションのhashが変わらないことを検査する。
- 仮置き取消後も見送り予測と施工プレビューが混同されず、主操作が残ることを画面マークアップ／smokeで検査する。

## iPhone 17 Proでの確認手順

1. 所有者限定の確認ページでステージ1を開始し、候補を選ぶ前に「見送り前の予測」の「現在」と「見送り後の予測」が読めることを確認する。
2. 候補を仮置きした状態でも、見送り予測は工事なしの予測として表示され、施工プレビューと混同しないことを確認する。
3. 仮置きを取消しても、候補・座標・見送り予測が壊れず、もう一度候補を選べることを確認する。
4. ステージ1の結果画面で、助言が「池にためる目標」と施工可能範囲を参照し、安全排水だけを勧めていないことを確認する。
5. ステージ2・3でも、目的に応じて助言の文言と見送り予測の成否・進捗・予測スコアが一致することを確認する。
6. 縦横画面、文字拡大、VoiceOver、WebGL有効時の盤面・水流・入力・発熱・復帰は別途確認し、自動検査の合格だけでM4完了とは扱わない。
